# LegalStart — бот MAX

Карточка `@se14597847_bot` создана в MAX для партнёров. Для рабочего запуска нужны одобрение модерации и токен. Само создание карточки не запускает Python-код.

## Запуск на Render после одобрения

Создайте **отдельный Web Service** из репозитория **GriGkos/LegalStart**, ветка `main`. Назовите его, например, `LegalStart-MAX`.

| Поле | Значение |
|---|---|
| Runtime | Python |
| Root Directory | Оставить пустым |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `python max_bot.py` |
| Compute | Free |
| Health Check Path | `/health` |

Добавьте переменные в **Environment** этого нового сервиса:

| Имя | Значение |
|---|---|
| `MAX_BOT_TOKEN` | Токен из MAX для партнёров → Чат-боты → ⋮ → Настройки |
| `MAX_WEBHOOK_SECRET` | Новый случайный секрет: 32–64 символа A-Z, a-z, 0-9, `_`, `-`. Используйте Generate |
| `MAX_ADMIN_CHAT_ID` | Сначала `0`; замените после команды `/id` именно в MAX |
| `DATABASE_URL` | Та же строка Supabase **Session pooler**, порт `5432`, что у Telegram-сервиса |
| `PYTHON_VERSION` | `3.12.11` |

Значение `DATABASE_URL` скопируйте между настройками сервисов, не публикуйте его. Токен MAX также вводите только в настройках сервиса. Токен Telegram для MAX не подходит.

`MAX_WEBHOOK_BASE_URL` и `PORT` на Render заполнять не нужно: платформа передаёт адрес сервиса и порт автоматически. MAX обращается к HTTPS-адресу на внешнем порту 443; приложение слушает внутренний `PORT`.

Нажмите Deploy и дождитесь **Live**. При старте приложение получает ID своего бота, подключает базу и регистрирует webhook `/max/webhook`. Полные тексты анкет, токены и строка подключения не выводятся в логи.

## Проверка и подключение администратора

1. Откройте одобренного бота `@se14597847_bot` в MAX и нажмите «Начать».
2. Отправьте `/id`. В ответе будут **ID чата MAX** и **ID пользователя MAX**.
3. Число из строки **ID вашего чата MAX** внесите в `MAX_ADMIN_CHAT_ID` нового сервиса Render. Telegram ID сюда не подходит.
4. Сохраните настройки и дождитесь перезапуска / Live.
5. Пройдите анкету с вымышленными ответами, проверьте ответы, исправьте один и отправьте заявку. Уведомление должно прийти в настроенный чат MAX.

При `MAX_ADMIN_CHAT_ID=0` заявка сохраняется, уведомления отключены. После подключения администратора бот доставит сохранённые заявки, которые ещё не были отмечены как доставленные.

## Что умеет версия

- Меню «О проекте», «Как это работает», FAQ и четыре вопроса анкеты.
- Проверка, исправление ответов и подтверждение отправки.
- `/start` возвращает меню и текущий шаг; `/cancel` удаляет черновик.
- Черновики и отправленные заявки сохраняются после перезапуска в PostgreSQL.
- Повторная доставка события не продвигает анкету дважды и не создаёт вторую заявку. Сообщение с результатом может повториться после сетевой ошибки.
- Уведомления администратору повторяются при временных ошибках. Если MAX получил уведомление, но ответ API потерялся, уведомление может прийти повторно.
- Принимаются текстовые ответы до 800 символов; документы перечисляются словами. Отвечает только в личных диалогах.

Эта версия отправляет текст и кнопки, без загрузки картинок с Unsplash. Она не зависит от доступности фотосервиса.

Telegram и MAX используют одну схему базы, но разные пространства `telegram:<id бота>` и `max:<id бота>`. Анкеты и очередь уведомлений разделены. В MAX уведомления приходят в MAX. Для одного MAX-бота запускайте только один экземпляр сервиса; не запускайте параллельно исходный polling-бот.

На сайте ссылка MAX пока отключена. После проверки рабочего бота можно указать его адрес в `site/src/config.ts` и пересобрать сайт.

## Ограничения бесплатного размещения

Render Free засыпает после 15 минут без входящих запросов. Первое сообщение или нажатие кнопки после простоя может обрабатываться с задержкой. Входящие webhook-запросы будят сервис; MAX повторяет запросы, если не получил успешный ответ. Это вариант для демо, без гарантии мгновенного ответа или непрерывной работы.

Если MAX не получает успешного ответа восемь часов, платформа может автоматически удалить подписку. После устранения ошибки перезапустите / переразверните сервис: приложение снова зарегистрирует подписку. Уведомления из очереди отправляются, пока сервис работает; во время сна фоновые попытки не выполняются.

Не храните базу в SQLite на Render Free: файловая система временная. Для запуска на своём сервере допускается SQLite через `MAX_DB_PATH`, но необходим публичный HTTPS webhook на порту 443.

## API и сертификаты

Клиент использует официальный `https://platform-api2.max.ru` и заголовок `Authorization`, без токена в URL. Дополнительный публичный сертификат Минцифры включён только в TLS-контекст клиента MAX. Проверка цепочки и имени сервера остаётся включённой; сертификат не устанавливается в систему. PostgreSQL использует собственный отдельный контекст в `storage.py`.

Источники протокола: [официальный обзор MAX API](https://dev.max.ru/docs-api), [OpenAPI MAX](https://github.com/max-messenger/api-schema), [подписки webhook](https://dev.max.ru/docs-api/methods/POST/subscriptions).

## Проверки кода

```powershell
python -m unittest -v test_bot test_max_bot
```

Тесты используют временную SQLite и имитацию API, не отправляют сообщения реальным людям. Проверяют всю анкету, редактирование, отмену, повторную доставку, перезапуск, разделение платформ, ID чата, уведомления, защиту webhook, JSON запросов и проверку TLS. Реальное подключение MAX проверяется после одобрения с настоящим токеном.
