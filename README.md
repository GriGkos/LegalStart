# LegalStart

В репозитории находятся сайт проекта и Telegram-бот.

| Часть | Файлы | Размещение |
|---|---|---|
| Сайт React/Vite | `site/` | Netlify |
| Telegram-бот | `bot.py`, `storage.py`, `requirements.txt` | Render |
| Настройки размещения | `netlify.toml`, `render.yaml` | Каждый сервис использует свою конфигурацию |

MAX-бот пока не включён. База хранится отдельно в Supabase.

## Размещение сайта на Netlify

В Netlify выберите импорт существующего проекта из GitHub и репозиторий **GriGkos/LegalStart**. Настройки уже записаны в корневом `netlify.toml`:

- Base directory: `site`.
- Build command: `npm run build`.
- Publish directory: `dist` (относительно `site`, полный путь — `site/dist`).
- Node.js: `24`.

Сайт собирается на Netlify; папка готовой сборки `dist` в GitHub не нужна. Страницы `/`, `/privacy` и `/terms` формируются существующим скриптом сборки.

Исходники сайта перенесены из LegalStart-source.zip без изменений. Telegram-ссылка пока указывает на username `ADVOKAT_PROJECTBOT`: при необходимости замените `TELEGRAM_BOT_USERNAME` в `site/src/config.ts`. MAX-ссылка пока пустая. Старый адрес `chatgpt.site` в метаданных можно заменить после получения адреса нового сайта.

Локальный запуск и сборка сайта описаны в [site/README.md](site/README.md).

Настройки Render остаются в корне: для Telegram-бота выберите этот же репозиторий и используйте `render.yaml`.

## Telegram-бот

Telegram-версия присланного MAX-бота. Здесь сохранены разделы «О проекте», «Как это работает», «Заполнить заявку» и FAQ, а также четыре вопроса анкеты. MAX-код и сайт не изменены.

Добавлены проверка и редактирование ответов перед отправкой, отмена, сохранение прогресса после перезапуска, обработка повторной доставки сообщений и повторные попытки уведомления администратора. Заявка сохраняется до попытки уведомления: ошибка отправки администратору не удаляет её.

Принимается текст, до 800 символов на ответ. Файлы не загружаются: документы нужно перечислить словами. Бот отвечает только в личных чатах. Картинки используются по тем же ссылкам Unsplash, что в MAX-коде; если Telegram не сможет получить картинку, раздел придёт текстом.

## Быстрая проверка на компьютере (Windows)

Нужен Python 3.10–3.14. Откройте PowerShell в папке с `bot.py`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Откройте `.env` и вставьте Telegram-токен от [@BotFather](https://t.me/BotFather) в `BOT_TOKEN`. Токен MAX не подходит. Оставьте `BOT_MODE=polling`, `DATABASE_URL` пустым и `ADMIN_CHAT_ID=0` для первого теста.

Запустите:

```powershell
.\.venv\Scripts\python.exe bot.py
```

Откройте бота в Telegram и отправьте `/start`. Для получения ID администратор должен открыть личный чат с ботом и отправить `/id`. Вставьте полученное число в `ADMIN_CHAT_ID` и перезапустите бота. Уведомления приходят только если пользователь не заблокировал бота. ID MAX и username Telegram сюда не подходят.

На компьютере заявки и прогресс сохраняются в `data/applications.db`. При закрытом компьютере бот не работает. Не запускайте второй экземпляр того же бота.

## Бесплатное размещение: Render + Supabase

Этот комплект размещает **только Telegram-бота**. Код MAX не включён. Оба бота можно объединить в одном web-сервисе позже, но для MAX потребуется отдельная адаптация webhook.

### 1. Создайте базу

1. Создайте проект на [Supabase Free](https://supabase.com/pricing).
2. Нажмите **Connect → Session pooler** и скопируйте PostgreSQL URI с портом **5432**.
3. Замените заглушку пароля на пароль базы. Если пароль содержит `@`, `:`, `/`, `#`, `%` или другие специальные символы, закодируйте их для URL; например `@` становится `%40`. Не присылайте строку подключения в чат.
4. Сохраните строку для настройки `DATABASE_URL` в Render. Обычно она начинается с `postgresql://postgres.<project-ref>:`. Код также принимает `postgres://`.

Выбирайте **Session pooler**, а не Transaction pooler с портом 6543. При подключении к PostgreSQL бот включает TLS с проверкой сертификата и имени сервера. Для Supabase корневой сертификат включён в `certs/supabase-prod-ca-2021.crt` и подключается автоматически. Дополнительные переменные окружения для SSL не нужны.

Бот сам создаст таблицы `legalstart_drafts`, `legalstart_applications` и `legalstart_events`. В каждой включается RLS без публичных политик: доступ к анкетам через публичный Supabase API закрыт. Сервер подключается как владелец базы `postgres`. Не открывайте эти таблицы анонимным пользователям.

Завершённые заявки можно смотреть в **Supabase → Table Editor → legalstart_applications**. Ответы хранятся в поле `answers` в порядке: ситуация, основной вопрос, обстоятельства, документы. Имена платформ содержат ID бота, поэтому данные разных ботов не смешиваются.

### 2. Загрузите код в GitHub

Создайте репозиторий и загрузите содержимое этой папки так, чтобы `bot.py`, `storage.py`, `requirements.txt` и `render.yaml` лежали в корне. Можно использовать приватный репозиторий.

Не загружайте `.env`, базу SQLite, папку `data` или `.venv`. Файл `.env.example` содержит только пустые настройки и подходит для репозитория.

### 3. Создайте сервис Render

В [Render](https://dashboard.render.com/) выберите **New → Blueprint**, подключите репозиторий и используйте включённый `render.yaml`.

Укажите `BOT_TOKEN` и `DATABASE_URL`. Шаблон создаст один бесплатный Python web-сервис, включит webhook и сгенерирует `WEBHOOK_SECRET`. Адрес сервиса бот возьмёт автоматически из `RENDER_EXTERNAL_URL`.

Либо настройте вручную **New → Web Service**:

| Настройка | Значение |
|---|---|
| Runtime | Python |
| Instance | Free |
| Build command | `pip install -r requirements.txt` |
| Start command | `python bot.py` |
| Health check | `/health` |
| `PYTHON_VERSION` | `3.12.11` |
| `BOT_MODE` | `webhook` |
| `BOT_TOKEN` | Telegram-токен от BotFather |
| `DATABASE_URL` | URI Supabase Session pooler, порт 5432 |
| `ADMIN_CHAT_ID` | ID чата Telegram, либо `0` |
| `WEBHOOK_SECRET` | Случайная строка из 16–256 символов A–Z, a–z, 0–9, `_`, `-` |
| `IMAGES_ENABLED` | `true`, либо `false` для работы без картинок |

Для генерации webhook-секрета локально:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

При запуске бот сам зарегистрирует `https://<имя-сервиса>.onrender.com/telegram/webhook`. Открывать URL с Telegram-токеном в браузере не нужно. Запросы без правильного секретного заголовка отклоняются.

После Deploy откройте бота, отправьте `/start`, затем `/id`. При необходимости добавьте `ADMIN_CHAT_ID` в Render → Environment и примените изменения.

### 4. Проверьте запуск

1. Откройте `/health` на адресе сервиса: должен вернуться `{"status":"ok"}`. Это проверка работы web-сервиса, а не доказательство доставки сообщений в Telegram.
2. В Telegram откройте меню, заполните четыре вопроса, измените один ответ и отправьте заявку.
3. Проверьте запись в Supabase и уведомление администратора.
4. Начните другую анкету, ответьте на первый вопрос, перезапустите сервис и отправьте `/start`: бот должен предложить второй вопрос.
5. Проверьте `/cancel`: незавершённая анкета удаляется. Ранее отправленные заявки сохраняются.

Тесты с настоящим токеном, внешней PostgreSQL-базой и реальное размещение пока не выполнены: для них нужны ваши настройки аккаунтов. Подключение к PostgreSQL реализовано, но проверено без подключения к внешней базе.

### Ограничения Free

Render Free засыпает после 15 минут без входящего трафика. Запрос Telegram разбудит сервер; первый ответ после простоя может задержаться примерно на минуту. При неудачной доставке Telegram повторяет webhook-запрос; повторные события не создают вторую заявку и не продвигают анкету дважды. Случайные повторные нажатия могут дать повторный ответ в чате.

Supabase Free приостанавливает проект после недели неактивности. Если бот не отвечает из-за приостановленной базы, возобновите проект в Supabase, затем перезапустите Render. Бесплатные тарифы подходят для демонстрации, но не обеспечивают непрерывную доступность.

Уведомления администратору проверяются каждые 15 секунд, пока сервис работает. При ошибке отправки заявка остаётся в базе и повторяется позже; во время сна Render отправка ждёт пробуждения. Возможен повтор уведомления, если сервер остановится сразу после отправки, но до сохранения отметки о доставке.

## Запуск на постоянном сервере

Можно оставить `BOT_MODE=polling` и SQLite на постоянном диске VPS. Запускайте процесс через менеджер служб с автоматическим перезапуском. Сохраняйте резервные копии базы и запускайте один экземпляр бота. Домен и входящий порт для polling не нужны.

## Проверки без Telegram

```powershell
.\.venv\Scripts\python.exe -m unittest -v test_bot
```

Используются временная SQLite-база и подменённый Telegram API: настоящий токен не нужен и сообщения не отправляются. Проверяются анкета, правки, отмена, повторная доставка, восстановление состояния, ограничения ввода, изоляция платформ, повторы уведомлений и защита webhook.

### Ошибка сертификата Supabase на Render

Если журнал показывает `CERTIFICATE_VERIFY_FAILED: self-signed certificate in certificate chain`, в меню **Manual Deploy → Deploy latest commit** повторите запуск последнего коммита с папкой `certs/`. Используйте исходное имя сервера из **Connect → Session pooler**, а не IP-адрес. Проверка цепочки сертификатов и имени сервера остаётся включённой.
